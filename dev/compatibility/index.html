Compatibility¶

This catalog is generated from Advect's live frontend bindings, public extension exports, and primitive registry — it documents what is qualified, not what happens to work.

The mode columns are public support claims: yes means the callable's declared contract is supported end to end in that execution mode (dynamic tracing, abstract staging, serialized artifacts). Restricted implementation paths may remain internal, but registration alone does not promote an additional upstream spelling into this catalog.

Abstract=yes means that a primitive has a standalone abstract rule. A frontend may still be staged by an explicit method or composite lowering when its displayed primitive does not.

Per-provider catalogs:

  • NumPy — 393 supported callable forms with installed NumPy 2.4.6 on the first-class protocol frontend
  • Array API — 169 namespace functions across three qualified standard revisions
  • CuPy — 169 Array API namespace functions in the designated single-device GPU gate; local evidence is not yet published
  • SciPy — 42 compatible functions and 2 solver adapters behind advect[scipy]
  • xarray — the labeled-array pytree contract behind advect[xarray]
